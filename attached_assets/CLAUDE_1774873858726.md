## What This Project Is

INSPIRE is a **behavioral profiling web app** that:
1. Asks users 24 behavioral questions + 8 scenario questions + 1 open question
2. Sends answers to an AI API (GPT-5.4 primary, Claude fallback)
3. Returns a personalized report with 8 sections
4. Delivers results via email and displays them on a results page

**This is NOT a chatbot. It is a structured assessment tool with a specific output format.**

## Critical Rules — Read Before Coding

### Rule 1: Arabic RTL is the default
- Root HTML: `<html lang="ar" dir="rtl">`
- Font: Tajawal (Arabic), Inter (English) from Google Fonts
- Every layout must work in RTL. Test mentally before writing.
- English-only content (code blocks, emails): `dir="ltr"` explicitly

### Rule 2: AI calls are server-side ONLY
- ANTHROPIC_API_KEY and OPENAI_API_KEY must NEVER reach the browser
- All AI generation happens in `/app/api/` route handlers
- Never import AI clients in any component file

### Rule 3: No assessment data is ever lost
- Save answers to DB immediately on submit (status: 'processing')
- If AI fails → status: 'pending_retry' (NOT 'failed')
- Cron job retries on schedule — see `/skills/ai-engine.md`
- Only mark 'failed' after 10 background retries

### Rule 4: The output has exactly 8 sections
Never simplify or merge these — each is stored separately in DB:
1. `inspire_table` (JSONB) — axis scores
2. `role_analysis` (TEXT) — composite role percentages
3. `red_lines` (JSONB) — string array, 4 items
4. `strengths` (JSONB) — string array, 4 items
5. `development_areas` (JSONB) — string array, 3 items
6. `recommendations` (JSONB) — string array, 4 items
7. `system_instruction` (TEXT) — full instruction
8. `quick_starters` (JSONB) — string array, 3 prompts

### Rule 5: User account is required before assessment
- Register → verify email → login → assess
- No anonymous assessments
- Email = unique user identifier
- Consent page must be shown and checkbox checked before registration

### Rule 6: INSPIRE acronym is specific
**I**ntention, **N**arrative, **S**tyle, **P**references, **I**nteraction, **R**eflection, **E**valuation
Do NOT use: Needs, Strategy, Patterns, Intuition, Rhythm, Influence (those are wrong)

## Build Order (follow this sequence)

Build in this exact order to avoid dependency issues:

```
Phase 1 — Foundation
  1. prisma/schema.prisma
  2. src/lib/db.ts
  3. src/data/questions.ts + scenarios.ts
  4. src/types/index.ts

Phase 2 — Auth
  5. src/lib/auth.ts (bcrypt + JWT)
  6. API: /auth/register, /auth/login, /auth/logout, /auth/refresh
  7. Pages: /privacy-consent, /register, /login

Phase 3 — Assessment Core
  8. src/lib/prompt-builder.ts
  9. src/lib/report-parser.ts
  10. src/lib/ai-engine.ts (GPT-5.4 + Claude fallback + retry)
  11. API: /assessments/start, /assessments/[id]/submit, /assessments/[id]/status
  12. Page: /assess (full flow, all steps)

Phase 4 — Results & Email
  13. src/lib/email.ts
  14. src/lib/pdf.ts
  15. API: /assessments/[id]/results, /assessments/[id]/pdf
  16. Page: /results/[id]

Phase 5 — User Area
  17. API: /users/me/assessments, /users/me/assessments/compare
  18. Page: /my-assessments

Phase 6 — Landing & Admin
  19. Page: / (landing)
  20. Admin pages + API routes
  21. API: /cron/retry

Phase 7 — Polish
  22. Mobile responsiveness
  23. RTL final check
  24. Error states and loading states
```
